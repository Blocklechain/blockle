Network upgrade

Cross-Algorithm Difficulty Coupling

Activates at block 53,000.

Blockle is merge-mined across ten algorithm lanes. Today each lane sets its own difficulty independently, which means every lane earns the same share of blocks no matter how much real energy backs it — an ultra-efficient ASIC lane is rewarded the same as a power-hungry one. At block 53,000 that changes.

What changes

All lanes are retargeted from one shared base difficulty, scaled per lane by a benchmark-measured energy-per-hash coefficient. Each lane must then expend the same real power per block, so block production — and therefore reward and security weight — tracks actual energy draw rather than raw hashrate. Fork-choice work is energy-weighted too, so the heaviest chain is the one backed by the most power.

This is a mining-difficulty and fork-choice rule only. No address formats, keys, balances, supply, or transaction rules change.

What you need to do

Node operators

Upgrade before block 53,000 — a node without this rule will reject post-fork blocks and split off the network.

git pull
cargo build --release
# restart your node service, e.g.
systemctl restart blockle-node

Confirm the rule is present: blockle-cli getblockchaininfo should include cross_algo_activation_height: 53000 and a live cross_algo_blocks_remaining.

Miners & pools

Point your miner/pool at an upgraded node. getblocktemplate returns the coupled difficulty bits automatically once you are on the new build — no pool config maths required. Payout addresses are unchanged. After the fork, your returns follow your share of real network power draw, not raw hashrate.

Wallet users

Nothing changes for your coins — addresses, keys and balances are unaffected. Just update to the latest Blockle wallet when prompted so you stay on the upgraded network. Get the latest wallet →

Why energy, not hashrate?

Coupling to measured energy-per-hash means reward and security both scale with the one thing an attacker actually has to spend — power. An efficient lane can no longer earn an outsized share or accumulate chain-work cheaply. The coefficients are fixed consensus constants derived from best-in-class hardware for each algorithm; the full methodology and the per-lane table are in the technical note below.
